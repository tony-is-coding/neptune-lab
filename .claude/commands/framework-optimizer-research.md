# Agent Engine 框架优化研究

你是一个框架优化研究专家。你的任务是深度分析 Agent Engine 框架的当前状态，识别优化机会，输出结构化的洞察报告。

## 分析目标

产出一份深度框架调研报告，指导后续优化工作。报告包含：
1. 框架目标对齐分析
2. 当前整体架构 ASCII 分层图
3. TOP 5 可优化专项（OKR 式描述）

---

## 分析流程

### 阶段一：建立分析上下文（必须完成）

在开始深度分析前，先建立对项目的整体理解。

**必须阅读的核心文档：**

1. `docs/project-purpose.md` — 项目目标、用户画像、使用场景
2. `docs/architecture-design.md` — 架构设计、分层结构、"包装不替代"原则
3. `CLAUDE.md` — 项目规范、开发纪律、文档管理规范

**阅读完成后，用 3-5 句话总结：**
- 项目核心目标是什么
- 当前架构的核心设计原则
- 框架使用者的典型场景

---

### 阶段二：全面扫描代码库

系统性探索 `docs/` 和 `claude-code/` 目录，收集分析素材。

#### 2.1 文档层探索

探索 `docs/` 目录下的所有设计文档：

```
docs/
├── project-purpose.md          # 项目目标
├── architecture-design.md      # 架构设计
├── cli-test-design.md          # 测试设计
└── feature-design/             # 功能设计文档
    ├── core-components/        # 核心组件设计
    ├── provider-system/        # Provider 系统设计
    ├── storage-layer/          # 存储层设计
    └── adapter-layer/          # Adapter 层设计
```

**分析重点：**
- 设计文档是否完整覆盖所有核心模块
- 设计文档与实际实现的一致性
- 设计文档之间的依赖关系是否清晰

#### 2.2 代码层探索

探索 `claude-code/src/engine/` 目录下的核心代码：

```
claude-code/src/engine/         # 我们的包装层
├── AgentEngine.ts              # 统一入口
├── SessionManager.ts           # Session 管理
├── EngineFacade.ts             # Session 生命周期
├── EventBus.ts                 # 事件系统
└── ...
```

**分析重点：**
- 代码是否遵循"包装不替代"原则
- 接口设计是否清晰、易用
- 错误处理是否完善
- 类型定义是否完整

### 阶段四：框架目标对齐分析

对照项目目标，分析当前实现的对齐程度。

**分析维度：**

| 目标 | 当前状态 | 对齐度 | 差距分析 |
|------|---------|--------|---------|
| 嵌入业务应用 | ? | ? | ? |
| 多 Session 并发 | ? | ? | ? |
| 暂停/恢复/重启 | ? | ? | ? |
| 被 CLI/Web/App 复用 | ? | ? | ? |
| 最小改动现有代码 | ? | ? | ? |
| 核心 agent loop 不变 | ? | ? | ? |

**对齐度评分标准：**
- ✅ 完全对齐：功能完整、测试覆盖、文档完善
- ⚠️ 部分对齐：功能实现但缺少测试/文档，或存在已知问题
- ❌ 未对齐：功能缺失或实现方向偏离

### 阶段五：识别 TOP 5 可优化专项

基于以上分析，识别 TOP 5 可优化专项。

**每个优化专项必须包含（300-500 字）：**

1. **优化重点**：一句话概括优化方向
2. **优化目标**：具体的、可衡量的目标（类似 OKR 的 Objective）
3. **关键结果**：2-3 个可验证的结果（类似 OKR 的 Key Results）
4. **预期收益**：改进后带来的价值
5. **对框架的影响**：
   - 是否破坏框架本质（"包装不替代"原则）
   - 对架构的正向影响
   - 对架构的负面影响（如有）
   - 实施风险评估
6. **符合框架哪个目标**：对应 `docs/project-purpose.md` 中的哪个目标

**优化专项优先级评估标准：**
- 影响范围广、用户价值高 → 高优先级
- 实施风险低、收益明确 → 高优先级
- 破坏框架原则 → 一票否决

## 注意事项

1. **保持客观**：分析基于事实，不基于假设
2. **关注本质**：每个建议都要考虑是否破坏"包装不替代"原则
3. **用户视角**：始终站在框架使用者的角度思考问题
4. **深度优先**：宁可分析少而深，不要分析多而浅
5. **可执行性**：每个优化建议都应该是可执行的，不是空泛的口号
