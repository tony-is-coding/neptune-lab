# 快速修复

## 原则

快，但不猜。先定位失败行为，再修改最小责任区域，验证后只汇报关键信息。

## 流程

1. 结论先行做初步判断：检查后用一句话说明最可能的问题区域。
2. 边界确认：明确本次涉及哪些文件/模块，以及哪些不会触碰。
3. 用最窄命令或代码阅读复现/确认问题。
4. 按本地风格修改最小责任模块。
5. 运行针对性验证：优先失败测试，其次相邻测试，必要时再跑更大范围。
6. 最终回复前自检：根因已处理、无无关改动、验证结果已记录、剩余风险已说明。

## 约束

- 最多问一个阻塞性问题。
- 不为局部 bug 重写架构。
- 不为了测试通过而修改测试，除非测试本身确实错误。
- 不新增依赖，除非修复必须需要且原因明确。

## 最终回复格式

先说结果。然后列出改动文件、验证命令/结果、剩余风险。
