# 0001: Mono-Repo 结构规范

- **日期**: 2026-05-03
- **状态**: accepted
- **决策者**: 团队

## 背景

仓库包含多个基于 neptune-engine SDK 的产品线。文档分散、CLAUDE.md 职责混乱、缺乏导航入口，需要建立统一的目录和文档规范。

## 决策

采用 CONTEXT.md / CONTEXT-MAP.md 驱动的文档导航体系，扁平产品线 + 顶层 shared/ 共享层结构。

## 方案对比

| 方案 | 优势 | 劣势 | 备注 |
|------|------|------|------|
| CONTEXT-MAP 导航体系（选定） | 扁平清晰、新产品接入成本低 | 需要维护 CONTEXT-MAP | |
| 传统 README 层级导航 | 无额外约定 | 深层嵌套难以发现 | |

## 后果

### 正面
- 所有产品线遵循统一的 CONTEXT.md 规范
- 各产品独立研发，通过 shared/ 共享跨产品资源
- 新产品只需创建目录和 CONTEXT.md 即可加入

### 负面
- 需要团队统一遵循 CONTEXT.md 格式约定
