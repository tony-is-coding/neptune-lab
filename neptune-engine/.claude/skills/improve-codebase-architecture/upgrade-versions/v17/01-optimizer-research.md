### 1.2 当前发现的关键问题

通过深度分析 V1-V16 完成后的代码状态，发现以下**生产就绪**相关的问题：

**质量保障维度（影响生产可靠性）**：
- TypeScript 类型错误残留（约 30+ 个），主要集中在 CLI 组件和测试文件
- 5 个 ProviderRegistry 测试失败（getRuntime 返回值问题）
- 105 个文件中仍存在 `as any`（404 处），类型安全有待加强
- 53 个文件包含 TODO/FIXME/XXX/HACK 技术债务标记

**可维护性维度（影响长期演进）**：
- 部分 engine/ 测试文件使用 mock.module 污染全局状态
- 测试用例中存在类型断言滥用（as unknown as SpecificType）
- 部分测试依赖外部状态（文件系统、环境变量），隔离性不足

**生产准备度维度（影响企业级采用）**：
- 缺少性能基准测试（无 benchmark）
- 缺少负载测试验证（无 stress test）
- 缺少生产级监控集成（Metrics、Tracing）
- 缺少故障恢复机制（Circuit Breaker、Retry）

## 三、优化清单（按优先级排序）

### Opt 1：TypeScript 类型错误清零（P0）

**优化重点**：清理残留的 TypeScript 类型错误，实现 tsc 零错误目标

**优化目标**：`bunx tsc --noEmit` 零错误通过

**关键结果**：
- KR1：修复 CLI 组件中的 ReactNode 类型错误（AssistantToolUseMessage、CollapsedReadSearchContent 等）
- KR2：修复 engine/ 测试文件中的类型断言问题（AgentEngine.test.ts、EngineState.test.ts）
- KR3：修复 builtin-tools 中的类型错误（WebFetchTool utils.ts）
- KR4：建立类型错误 CI 检查，防止回归
- KR5：新增 10+ 个类型安全测试用例

**预期收益**：
- 编译时类型安全保障
- IDE 提示更准确
- 防止类型相关的运行时错误

**对框架的影响**：
- 不破坏框架原则 — 只修复类型错误
- 正向：类型安全提升，生产可靠性增强
- 负面：部分测试代码需要调整（避免类型断言）
- 风险：低 — 主要是测试文件和 CLI 组件

**符合框架目标**：tsc 零错误（architecture-design.md 五、质量指标）

**依赖关系**：无
