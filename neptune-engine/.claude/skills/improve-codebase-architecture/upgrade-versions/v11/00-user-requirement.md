# 用户需求记录

> 记录时间: 2026-04-28

## 原始需求

基于 OKR 路线图（docs/okr-roadmap.md），一次性将 5 个版本（V1-V5）梳理好清晰的任务，进行深度探索，在一个版本周期内完成。

## 需求澄清

1. **优化目标**: 全量架构治理 — 覆盖 OKR 路线图 V1 到 V5 全部 5 个版本
2. **关注范围**: claude-code/ 全目录，重点 engine/、utils/、services/
3. **执行方式**: 一次性深度分析 + 任务拆分，覆盖全部版本
4. **特殊约束**: 用户授权自主决策，按照最佳要求执行
5. **产出要求**: 每个版本清晰的 KR、任务清单、依赖关系、验证标准

## 5 个版本目标

### V1：CLI 外化 + SDK 目录干净
- 解决缺陷 1（CLI 混入 SDK）、缺陷 2（utils/services 混合 — CLI 部分）
- 目标：SDK 和 CLI 各自可独立构建

### V2：分层治理 + 外部可用
- 解决缺陷 3（54 处穿透）、缺陷 5（工具静态注册）、缺陷 10（无 lint:layers）
- 目标：外部项目可直接引用 claude-code/ 使用 Agent 能力

### V3：Provider 整合 + 上下文工程增量 + Backend 抽象
- 解决缺陷 4（Provider 空壳）、缺陷 6（无卸载）、缺陷 7（无 Backend 抽象）
- 目标：真实可用的 Provider 体系和上下文卸载能力

### V4：生产加固
- 解决缺陷 8（日志无 JSON）、缺陷 9（权限只有只读）
- 目标：日志和权限系统达到生产标准

### V5：文档 & 交付验收
- 目标：文档完备，workspace 引用验证通过

## 完成标准

- 每个版本有清晰的任务清单（含文件级粒度）
- 每个任务有明确的验证标准
- 版本间依赖关系明确
- 风险和缓解措施清晰
