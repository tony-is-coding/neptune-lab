# Agent Engine 项目目标

> 更新时间：2026-04-29（V19 完成 · 文档数据同步）
> 文档状态：最新

---

## 一、核心定位

**一句话定义**：将 Claude Code 的核心 Agent 能力解耦为独立 SDK（Agent Engine），使其可以被嵌入任意应用，而无需依赖 CLI/TUI 宿主。

**核心原则**：
- **包装不替代**（最高原则）：框架的核心是扩展 Claude Code，不是从头构建
- **最小改动现有代码**：优先包裹和外扩，核心 agent loop 尽量不变
- **渐进式推进**：每个版本做到位再继续，不设硬性截止时间

**终极目标**：根目录只包含 SDK 核心需要的内容，CLI/TUI/产品级功能物理分离到独立目录。

---

## 二、项目背景

### 当前痛点

- Claude Code 的核心执行能力与 CLI 宿主紧耦合
- 无法被其他应用（Web/App/服务端）复用
- 不支持多 Session 并发
- 缺少暂停/恢复/重启能力

### 解决方案

将核心执行能力从 CLI 中解耦，沉淀为通用 Agent Engine SDK 底座。

## 四、使用场景

### 场景 1：嵌入式 SDK（核心场景）

用户在自己的应用中通过 npm 包集成 Agent 能力。

```typescript
import { AgentEngine } from '@anthropic/agent-engine'

const engine = AgentEngine.create({
  systemPrompt: '你是一个代码助手',
  provider: {
    type: 'openai',
    config: { apiKey: 'sk-xxx', model: 'gpt-4o' }
  },
  extensions: { tools: [myCustomTool] },
  toolsets: ['core', 'filesystem'],  // 按需加载工具组
})

const sessionId = await engine.createSession({ workspace: '/path/to/project' })

// 拉模式
for await (const msg of engine.query(sessionId, '分析这个文件')) {
  console.log(msg)
}

// 推模式
engine.on('assistant', (msg) => { /* 处理助手回复 */ })
```

### 场景 2：Web 服务

Express/Koa 中创建 AgentEngine，通过 HTTP API 对外提供 Agent 服务。

- 支持 SSE/WebSocket 流式响应
- 支持多用户并发
- 支持 Session 管理和恢复

### 场景 3：自动化任务

作为后台任务执行 Agent 工作流。

- CI/CD 集成（代码审查、自动修复）
- 定时任务（代码分析、报告生成）
- 后台队列（BullMQ/Agenda 集成）
- 支持 headless 运行（零 UI 依赖）

### 场景 4：CLI 工具

现有 Claude Code CLI 作为 SDK 的一个上层宿主。

- 保持现有 CLI 全部能力
- 通过 SDK 统一管理 Session
- 支持交互式和非交互式模式

## 六、技术目标

### 核心架构目标

1. **物理分离**：`src/` 只包含 SDK 核心，CLI/TUI 移到 `claude-code-cli/`
2. **零 UI 依赖**：SDK 打包后零 React/Ink 依赖
3. **独立发布**：可通过 `npm install` 独立安装使用
4. **完整能力**：SDK 暴露 Claude Code 的全部核心能力（55+ 工具、权限、上下文、Hook）

### 技术约束

- 核心模块使用 Claude Code 原始实现（QueryEngine、tools、permissions），不重建
- engine/ 目录作为框架包装层，提供 SDK 友好接口
- 所有核心状态零 React 依赖（通过 EngineState、CoreAppState 管理）
- 事件完全透传 Claude Code 原始 Message（不自建事件模型）

## 八、"完成"的定义

Agent Engine SDK 项目算"完成"的标准：

1. **物理分离完成**：根目录只包含 SDK 核心，零 CLI/TUI 代码
2. **独立发布就绪**：可独立 `npm publish`，有完整的类型声明和 API 文档
3. **分层验证通过**：lint:layers 零违规，tsc 零错误
4. **回归验证通过**：现有 CLI 功能通过上层宿主继续正常工作
5. **性能达标**：多 Session 并发 ≥ 10，SDK 包 < 2MB
6. **文档同步**：架构文档、设计文档、API 文档全部反映最终状态
