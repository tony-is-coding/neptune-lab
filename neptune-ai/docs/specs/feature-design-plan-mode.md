# Plan 模式支持 — 产品设计文档

## 一、产品目标

**核心目标**：让 Agent 处理复杂任务时，先制定清晰的执行计划，让用户了解"将要做什么"，并允许用户在执行前干预。

**用户体验原则**：
- 复杂任务先计划，后执行
- 计划可视化，步骤清晰
- 用户可以暂停、修改、取消计划

---

## 二、用户故事

### US1: 复杂任务先看到计划
**作为** 业务人员
**我想要** 给 Agent 下达复杂任务时，先看到它将如何执行
**以便** 确认方向正确，避免浪费资源跑偏

### US2: 计划执行中看到进度
**作为** 业务人员
**我想要** 在计划执行过程中，看到每一步的进度
**以便** 了解任务完成情况，预估剩余时间

### US3: 执行中可以暂停/取消
**作为** 业务人员
**我想要** 发现 Agent 走偏时，能够暂停或取消执行
**以便** 及时调整方向，不浪费时间和资源

### US4: 执行失败后智能恢复
**作为** 业务人员
**我想要** 某一步失败时，Agent 能够智能重试或跳过
**以便** 任务能够继续完成，而不是全部重来

## 三、交互设计

### 3.1 Plan 的触发条件

**自动触发**（Agent 判断）：
- 任务包含 3 个以上步骤
- 任务涉及多个工具调用
- 用户明确说"制定计划"或"先规划"

**用户主动触发**：
- 点击"先计划再执行"按钮（新增 UI）

### 3.3 用户交互操作

#### 修改计划

**场景**：用户看到计划后想调整某一步

```

├─────────────────────────────────────────┤

│                                          │
```

**实现方式（Phase 1 简化版）**：
- 用户只能给 Agent 发送反馈："请把第 2 步改为包含预测"
- Agent 重新生成计划

```
│                                          │
```

#### 单步失败（可重试）

## 四、Plan 数据结构设计

### 4.1 前端数据结构

```typescript
interface Plan {
  id: string;                    // Plan 唯一 ID
  status: 'pending' | 'awaiting_confirmation' | 'running' | 'paused' | 'completed' | 'failed' | 'cancelled';
  steps: PlanStep[];
  metadata: {
    totalEstimatedTime?: number;  // 秒
    actualTime?: number;          // 秒
    createdAt: number;
    startedAt?: number;
    completedAt?: number;
  };
}

interface PlanStep {
  id: string;
  index: number;                  // 步骤序号（从 1 开始）
  title: string;                  // 用户友好的标题
  description?: string;           // 详细描述
  toolName?: string;              // 将要调用的工具
  toolInput?: Record<string, unknown>;  // 工具输入参数
  status: 'pending' | 'running' | 'completed' | 'failed' | 'skipped' | 'cancelled';
  estimatedTime?: number;         // 秒
  actualTime?: number;            // 秒
  progress?: number;              // 0-100
  error?: {
    message: string;
    retryable: boolean;
  };
  output?: unknown;               // 步骤执行结果
}
```

## 五、验收标准（AC）

### AC1: 计划自动生成
**Given** 用户下达包含 3+ 步骤的复杂任务
**When** Agent 判断需要制定计划
**Then**
- 显示 "正在制定计划..." 提示
- 3-5 秒内展示完整计划
- 计划包含步骤标题、工具、预计时间

### AC2: 计划确认执行
**Given** Plan 已展示给用户
**When** 用户点击 [开始执行]
**Then**
- Plan 状态变为 "执行中"
- 当前步骤高亮显示
- 实时更新进度

### AC3: 执行进度可视化
**Given** Plan 正在执行中
**When** 执行到第 2 步
**Then**
- 第 1 步显示 "已完成" + 绿色勾
- 第 2 步显示 "执行中" + 蓝色高亮 + 进度条（如果有）
- 第 3 步显示 "等待中" + 灰色

### AC4: 暂停/恢复功能
**Given** Plan 正在执行中
**When** 用户点击 [暂停]
**Then**
- 当前步骤暂停
- 显示 "执行已暂停" 状态
- 提供 [恢复执行] 按钮
- 点击 [恢复执行] 后从暂停处继续

### AC5: 失败重试
**Given** Plan 执行中某一步失败
**When** 失败发生
**Then**
- 失败步骤显示红色叉 + 错误原因
- 提供 [重试]、[跳过]、[修改后重试] 选项
- 选择 [重试] 后重新执行该步骤

### AC6: 取消执行
**Given** Plan 正在执行中
**When** 用户点击 [取消] 并确认
**Then**
- 显示确认对话框
- 确认后停止执行
- 已完成的步骤保留，未完成步骤标记为 "已取消"
- Agent 输出取消摘要

### AC7: Plan 完成
**Given** Plan 所有步骤完成
**When** 最后一步完成
**Then**
- 所有步骤显示绿色勾
- 显示总耗时
- 提供 [重新执行]、[查看结果] 按钮
- Agent 输出任务完成摘要

## 六、边界场景处理

### 6.1 计划制定超时

**场景**：Agent 制定计划超过 10 秒

**处理**：
```
┌─────────────────────────────────────────┐
│ ⏳ 正在制定计划，请稍候...                │
│ 已耗时: 10 秒                            │
│                                          │
│ [取消]  [继续等待]                        │
└─────────────────────────────────────────┘
```

### 6.2 用户不确认计划

**场景**：计划已展示，用户 5 分钟无操作

**处理**：
- Plan 不自动执行
- 保持 "等待确认" 状态
- 用户可以随时回来点击 [开始执行]

### 6.3 执行中用户关闭页面

**场景**：Plan 执行中，用户关闭浏览器

**处理**：
- 后端继续执行（如设计支持）
- 用户回来后显示 "Plan 已在后台执行"
- 提供查看结果的选项

### 6.4 计划步骤依赖失败

**场景**：第 2 步依赖第 1 步的输出，第 1 步失败

**处理**：
- 标记第 2 步为 "无法执行"（blocked）
- 提示用户：需要先修复第 1 步
- 提供 "从第 1 步重新执行" 选项

### 6.5 Agent 判断错误

**场景**：Agent 生成计划后，发现无法执行

**处理**：
```
┌─────────────────────────────────────────┐
│ ⚠️ 计划需要调整                          │
├─────────────────────────────────────────┤
│ Agent 发现原计划不可行，需要修改：        │
│                                          │
│ 原步骤 2: analyze_trend                  │
│ 问题: 工具暂时不可用                      │
│                                          │
│ 建议改为: analyze_basic                  │
│                                          │
│ [接受修改]  [取消执行]                    │
└─────────────────────────────────────────┘
```

## 七、非技术用户体验要点

1. **语言友好**：
   - ❌ "Step 2: execute_tool(read_file)"
   - ✅ "步骤 2: 读取文件"

2. **进度可见**：
   - 总是显示当前进度（2/5）
   - 预估剩余时间

3. **操作明确**：
   - 每个操作都有明确的按钮
   - 危险操作（取消）需要确认

4. **错误可恢复**：
   - 失败不意味着重来
   - 提供多种恢复选项

---

## 八、Phase 1 范围（MVP）

**包含**：
- ✅ Plan 自动生成和展示
- ✅ 用户确认后执行
- ✅ 执行进度可视化
- ✅ 单步失败重试
- ✅ 取消执行

**不包含（Phase 2）**：
- ❌ 用户手动修改计划
- ❌ 计划模板保存
- ❌ 多 Agent 协作计划
- ❌ 计划执行历史回顾

---

## 九、后续优化方向（Phase 2+）

1. **计划模板**：用户可以保存常用计划模板
2. **计划共享**：团队成员可以共享和复用计划
3. **智能建议**：基于历史数据优化计划
4. **并行执行**：支持无依赖步骤并行执行
