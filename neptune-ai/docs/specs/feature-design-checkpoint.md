# 用户澄清 UI（Checkpoint）— 产品设计文档

## 一、产品目标

**核心目标**：当 Agent 执行中需要用户确认/选择时，优雅地中断并等待用户输入，让 Agent 能够安全、准确地完成任务。

**用户体验原则**：
- 澄清时机自然，不打断用户心流
- 选择界面简洁，选项明确
- 超时后有合理默认处理

---

## 二、用户故事

### US1: 危险操作前确认
**作为** 业务人员
**我想要** Agent 执行危险操作（如删除数据）前询问我
**以便** 避免误操作造成损失

### US2: 多个选项中选择
**作为** 业务人员
**我想要** Agent 遇到歧义时，让我从几个选项中选择
**以便** 确保它按照我的意图执行

### US3: 补充必要信息
**作为** 业务人员
**我想要** Agent 缺少必要信息时，询问我具体细节
**以便** 不需要我重新描述整个任务

### US4: 长时间不响应自动处理
**作为** 业务人员
**我想要** 当我离开无法响应时，Agent 能够按默认策略继续
**以便** 任务不会因为我的缺席而完全停滞

## 三、交互设计

### 3.1 Checkpoint 触发场景

| 场景 | 示例 | Checkpoint 类型 |
|------|------|-----------------|
| 危险操作 | "准备删除 100 条记录，确认？" | 确认框（是/否） |
| 多选歧义 | "找到 3 个匹配文件，请选择：" | 单选列表 |
| 缺少参数 | "请问导出格式选择 PDF 还是 Excel？" | 单选按钮 |
| 自由输入 | "请提供数据库密码：" | 输入框（遮蔽） |
| 数量确认 | "预计处理 5000 条记录，确认继续？" | 确认框（是/否/取消） |

### 3.2 Checkpoint UI 设计

#### 基础确认框（Yes/No）

```
┌─────────────────────────────────────────┐
│ Agent: 正在执行任务...                   │
│ ⏳ 步骤 2/3: 清理过期数据                 │
└─────────────────────────────────────────┘

┌─────────────────────────────────────────┐
│ ⚠️ 需要您的确认                          │
├─────────────────────────────────────────┤
│ Agent 准备执行以下操作：                  │
│                                          │
│ • 删除 2023 年之前的过期记录             │
│ • 影响范围: 约 1,200 条                  │
│                                          │
│ 此操作不可撤销，请确认是否继续？          │
├─────────────────────────────────────────┤
│ [取消]           [确认删除]               │
│                  ↑ 红色按钮               │
└─────────────────────────────────────────┘
```

**视觉规范**：
- 弹窗从底部滑入（Mobile 友好）
- 背景：半透明遮罩（`bg-black/50`）
- 警告类：黄色/橙色强调色
- 危险操作（删除）：红色确认按钮

#### 单选列表

```
┌─────────────────────────────────────────┐
│ 📋 请选择要处理的文件                    │
├─────────────────────────────────────────┤
│ 找到 3 个匹配文件，请选择：               │
│                                          │
│ ◉ sales_q3_2024.csv                     │

│                                          │

│                                          │
│ ○ sales_q3_draft.csv                    │
│   大小: 1.8 MB | 更新: 2024-09-30        │
│                                          │
├─────────────────────────────────────────┤
│ [取消]  [全选]  [确认选择]               │
└─────────────────────────────────────────┘
```

**交互细节**：
- 支持键盘导航（↑↓ 选择，Enter 确认）
- 选项描述清晰（大小、日期等辅助信息）
- 多选时显示已选数量

#### 输入框（敏感信息）

```
┌─────────────────────────────────────────┐
│ 🔐 需要认证信息                          │
├─────────────────────────────────────────┤
│ 请提供数据库访问密码：                    │
│                                          │
│ ┌─────────────────────────────────────┐ │
│ │ ••••••••                            │ │
│ └─────────────────────────────────────┘ │
│                                          │
│ ℹ️ 密码仅用于本次操作，不会被保存         │
├─────────────────────────────────────────┤
│ [取消]  [确认]                            │
└─────────────────────────────────────────┘
```

**安全特性**：
- 密码自动遮蔽
- 明确告知不保存
- 输入框自动聚焦

### 3.3 超时处理

#### 超时倒计时 UI

```
┌─────────────────────────────────────────┐
│ ⏰ 等待您的响应                          │
├─────────────────────────────────────────┤
│ Agent 准备删除过期记录...                 │
│                                          │
│ [取消]  [确认]                            │
│                                          │
│ ⏱️ 60 秒后将自动取消操作                  │
│ ████████████░░░░░░░░░░ 60s               │
└─────────────────────────────────────────┘
```

#### 超时后的行为

**默认策略**（可配置）：
1. **安全类**（删除、修改）：超时 = 自动取消
2. **查询类**（读取、导出）：超时 = 使用第一个选项
3. **输入类**（密码、参数）：超时 = 取消操作

**超时后提示**：
```
┌─────────────────────────────────────────┐
│ ⏰ 等待超时                               │
├─────────────────────────────────────────┤
│ 由于长时间未响应，操作已自动取消。         │
│                                          │
│ [重新发起]  [关闭]                        │
└─────────────────────────────────────────┘
```

### 3.4 Checkpoint 状态流转

```
[Agent 执行中]
    ↓
[遇到需要确认的操作]
    ↓
[发送 Checkpoint 事件] → [前端弹窗]
    ↓
[等待用户响应] ← (超时) → [默认处理]
    ↓
[用户选择]
    ↓
[发送响应给后端]
    ↓
[Agent 继续执行]
```

## 四、数据结构设计

### 4.1 Checkpoint 事件结构

```typescript
// 后端 → 前端：Checkpoint 请求事件
interface SSECheckpointEvent {
  type: 'checkpoint';
  data: {
    checkpointId: string;
    question: string;              // 用户友好的问题
    description?: string;          // 补充说明
    checkpointType: 'confirmation' | 'single_choice' | 'multiple_choice' | 'input' | 'secure_input';
    options?: CheckpointOption[];
    defaultOption?: string | number;  // 超时默认选项
    timeout?: number;              // 超时秒数（0 = 不超时）
    metadata?: {
      toolName?: string;           // 触发的工具名
      operation?: string;          // 操作描述
      riskLevel?: 'low' | 'medium' | 'high';  // 风险等级
    };
  };
}

interface CheckpointOption {
  id: string;
  label: string;                  // 显示文本
  description?: string;           // 辅助说明
  value: unknown;                 // 实际值
  isDefault?: boolean;            // 是否默认选项
  isDestructive?: boolean;        // 是否危险操作
}

// 前端 → 后端：Checkpoint 响应
interface CheckpointResponse {
  checkpointId: string;
  response: {
    type: 'accept' | 'decline' | 'option' | 'input';
    selectedOptions?: string[];   // 选项 ID
    inputValue?: string;          // 输入值
  };
}
```

### 4.2 前端状态管理

```typescript
interface CheckpointState {
  isActive: boolean;
  currentCheckpoint?: {
    id: string;
    question: string;
    type: CheckpointType;
    options?: CheckpointOption[];
    timeoutAt?: number;           // 过期时间戳
  };
  history: CheckpointHistoryItem[];  // 历史记录
}

interface CheckpointHistoryItem {
  id: string;
  question: string;
  userResponse: string;
  timestamp: number;
  duration: number;  // 响应用时（秒）
}
```

## 五、验收标准（AC）

### AC1: 危险操作确认
**Given** Agent 准备执行删除操作
**When** 操作需要确认
**Then**
- 显示确认弹窗
- 明确说明操作影响（如"删除 1,200 条记录"）
- 确认按钮为红色
- 用户必须明确确认才能继续

### AC2: 单选列表交互
**Given** Agent 需要用户从多个选项中选择
**When** 显示单选列表
**Then**
- 所有选项清晰展示
- 单选按钮（○/◉）明确标识
- 支持键盘导航
- 必须选择才能确认

### AC3: 敏感信息输入
**Given** Agent 需要用户提供密码
**When** 显示密码输入框
**Then**
- 输入内容自动遮蔽（••••）
- 显示"不会被保存"提示
- 输入框自动聚焦
- 支持 Enter 快捷确认

### AC4: 超时自动处理
**Given** Checkpoint 等待用户响应
**When** 超过配置的超时时间（如 60 秒）
**Then**
- 显示倒计时进度条
- 超时后执行默认策略（安全类 = 取消）
- 显示超时提示
- 提供"重新发起"选项

### AC5: 响应后继续执行
**Given** Checkpoint 等待中
**When** 用户做出选择并确认
**Then**
- 弹窗立即关闭
- Agent 收到响应并继续执行
- 对话流无缝衔接

### AC6: 用户取消 Checkpoint
**Given** Checkpoint 等待中
**When** 用户点击取消
**Then**
- 弹窗关闭
- Agent 收到取消信号
- 任务中止或回退
- 显示"操作已取消"提示

### AC7: 多个 Checkpoint 串联
**Given** 任务需要多次用户确认
**When** 第一个 Checkpoint 完成
**Then**
- Agent 继续执行到下一个需要确认的点
- 显示新的 Checkpoint
- 历史记录可查看

## 六、边界场景处理

### 6.1 Checkpoint 期间网络断开

**场景**：用户正在选择时，网络断开

**处理**：
```
┌─────────────────────────────────────────┐
│ ⚠️ 连接已断开                            │
├─────────────────────────────────────────┤
│ 您的选择可能无法送达。                    │
│                                          │
│ • 等待连接恢复后重试                      │
│ • 取消并重新开始任务                      │
│                                          │
│ [重试]  [取消任务]                        │
└─────────────────────────────────────────┘
```

### 6.2 Agent 在 Checkpoint 前崩溃

**场景**：Agent 发送 Checkpoint 后，在等待响应时崩溃

**处理**：
```
┌─────────────────────────────────────────┐
│ ⚠️ Agent 连接中断                        │
├─────────────────────────────────────────┤
│ Agent 在等待响应时意外断开。              │
│                                          │
│ 您的输入不会被保存。                      │
│                                          │
│ [关闭]                                   │
└─────────────────────────────────────────┘
```

### 6.3 用户快速连续操作

**场景**：用户快速点击多个选项

**处理**：
- 防抖：500ms 内只处理最后一次选择
- 按钮状态：处理中禁用

### 6.4 Checkpoint 与 Plan 冲突

**场景**：Plan 执行中触发 Checkpoint

**处理**：
```
┌─────────────────────────────────────────┐
│ 📋 执行计划 (3 个步骤)                   │
├─────────────────────────────────────────┤
│ ✅ 步骤 1: 查询数据                       │
│ ⏸️ 步骤 2: 删除记录 (等待确认)            │ ← Plan 暂停
│ ⏸️ 步骤 3: 生成报告                       │
└─────────────────────────────────────────┘

┌─────────────────────────────────────────┐
│ ⚠️ 需要您的确认                          │
│ [确认删除弹窗...]                        │
└─────────────────────────────────────────┘
```

### 6.5 用户长时间不在线

**场景**：Checkpoint 超时后，用户仍未回来

**处理**：
- 任务按默认策略处理（通常是取消）
- 记录到 Checkpoint 历史
- 用户回来后显示"由于长时间未响应，任务已取消"

## 七、后端 API 需求

### 7.1 新增 SSE 事件

| 事件 | 方向 | 说明 |
|------|------|------|
| `checkpoint` | 后端→前端 | 请求用户确认 |
| `checkpoint_timeout` | 后端→前端 | 超时通知 |
| `checkpoint_cancelled` | 后端→前端 | Agent 取消了 checkpoint |

### 7.2 新增 HTTP 端点

```
POST /api/v1/agents/:agentId/threads/:threadId/checkpoint/:checkpointId/response
Body: {
  response: {
    type: 'accept' | 'decline' | 'option' | 'input',
    selectedOptions?: string[],
    inputValue?: string
  }
}
```

## 八、非技术用户体验要点

1. **问题清晰**：
   - ❌ "Confirm deletion"
   - ✅ "确认删除 1,200 条 2023 年之前的记录？"

2. **选项明确**：
   - 每个选项都有清晰的标签
   - 必要时补充说明

3. **风险提示**：
   - 危险操作用红色/橙色强调
   - 明确说明"不可撤销"

4. **默认安全**：
   - 超时默认选择安全的选项（通常是取消）
   - 危险操作需要明确确认

## 九、Phase 1 范围（MVP）

**包含**：
- ✅ 确认框（Yes/No）
- ✅ 单选列表
- ✅ 基础输入框
- ✅ 超时处理（60 秒）
- ✅ Checkpoint 历史

**不包含（Phase 2）**：
- ❌ 多选列表
- ❌ 复杂表单（多字段输入）
- ❌ 文件上传
- ❌ 富文本预览

---

## 十、后续优化方向（Phase 2+）

1. **智能默认**：基于历史行为预测用户选择
2. **批量确认**：多个相似 checkpoint 合并确认
3. **预设策略**：用户可配置"自动确认所有安全操作"
4. **权限控制**：不同用户对不同 checkpoint 的权限
