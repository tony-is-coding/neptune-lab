# SSE 流式体验优化 — 产品设计文档

## 一、产品目标

**核心目标**：让用户感受到 Agent 正在"实时思考和打字"，消除等待焦虑，提升对话流畅度。

**用户体验原则**：
- 等待不应是"黑盒"，用户需要知道 Agent 正在工作
- 文字应该逐字出现，模仿人类打字效果
- 长时间等待时提供进度指示

---

## 二、用户故事

### US1: 发送消息后立即看到反馈
**作为** 业务人员
**我想要** 发送消息后立即看到"Agent 正在思考"的提示
**以便** 确认我的消息已被接收，系统正在处理

### US2: 文字逐字流式出现
**作为** 业务人员
**我想要** Agent 的回复像真人打字一样逐字出现
**以便** 感到 Agent 正在实时与我交流，而不是等待后突然出现一大段文字

### US3: 长时间等待时看到进度
**作为** 业务人员
**我想要** 当 Agent 执行复杂任务时，看到它在做什么（如"正在查询数据库..."）
**以便** 知道系统没有卡死，理解 Agent 的工作状态

### US4: 网络异常时友好提示
**作为** 业务人员
**我想要** 当网络断开时，看到清晰的错误提示和重试选项
**以便** 能够快速恢复对话，而不是困惑发生了什么

## 三、交互设计

### 3.1 发送消息后的即时反馈

**时机**：用户点击发送按钮 → 立即（<100ms）

**UI 变化**：
```
┌─────────────────────────────────────────┐
│ [输入框]                    [发送按钮]   │ ← 输入框清空，发送按钮禁用
└─────────────────────────────────────────┘

↓ 立即出现 ↓

┌─────────────────────────────────────────┐
│ [用户消息] 你好，帮我查一下...           │
└─────────────────────────────────────────┘
┌─────────────────────────────────────────┐
│ ○ 正在思考...                            │ ← 灰色小圆点 + 省略号动画
└─────────────────────────────────────────┘
```

**视觉规范**：
- 状态指示器：灰色小圆点（∘ 8px）+ "正在思考..." 文字
- 动画：省略号每秒变化（... → .. → . → ...）
- 位置：消息气泡左上角，与后续文字对齐

### 3.2 文字流式输出效果

**效果定义**：
- 文字按字符或小词组（2-3 字）逐步出现
- 速度：约 30-50 字/秒（人类打字速度的 1.5-2 倍）
- 光标：末尾有闪烁的光标（|），直到完成

**视觉效果**：
```
[流式中]
Agent: 你好！我来帮你看一下这个问_
                                    ↑ 闪烁光标

[完成后]
Agent: 你好！我来帮你看一下这个问题。
```

### 3.3 工具调用的状态展示

当 Agent 调用工具时，显示工具执行状态：

```
Agent: 正在查询数据库...
┌─────────────────────────────────┐
│ 🔍 search_database              │
│ 输入: { query: "销售数据" }      │
│ ⏳ 执行中...                     │
└─────────────────────────────────┘

[工具完成后]
┌─────────────────────────────────┐
│ ✅ search_database               │
│ 耗时: 1.2s                       │
└─────────────────────────────────┘

Agent: 根据查询结果，本月销售额为...
```

### 3.4 长时间等待的进度提示

**阈值定义**：
- 3 秒：显示 "正在思考..." + 加载动画
- 10 秒：显示 "正在执行复杂任务，请稍候..."
- 30 秒：显示 "正在处理中，已耗时 30 秒..." + 取消按钮

**UI 设计**：
```
[30 秒后]
┌─────────────────────────────────────────┐
│ ⏳ 正在处理中，已耗时 30 秒...            │
│                                          │
│ [取消执行]  [继续等待]                    │
└─────────────────────────────────────────┘
```

### 3.5 网络异常处理

**场景 1：SSE 连接断开**
```
┌─────────────────────────────────────────┐
│ ⚠️ 连接已断开                            │
│                                          │
│ 最后收到: "根据查询结果，本月..."         │
│                                          │
│ [重新连接]  [复制未完成内容]              │
└─────────────────────────────────────────┘
```

**场景 2：发送失败（网络错误）**
```
┌─────────────────────────────────────────┐
│ ❌ 发送失败                               │
│                                          │
│ 请检查网络连接后重试                      │
│                                          │
│ [重试]  [取消]                            │
└─────────────────────────────────────────┘
```

## 四、状态机设计

### 4.1 消息状态流转

```
[用户发送]
    ↓
[sending] —(网络错误)→ [error]
    ↓
[thinking] —(3s)→ [processing] —(30s)→ [long_running]
    ↓
[streaming] ←──────┘
    ↓
[complete]
```

### 4.2 状态对应的 UI 表现

| 状态 | UI 表现 | 可操作 |
|------|---------|--------|
| `sending` | 输入框禁用，消息出现"发送中..." | 无 |
| `thinking` | "正在思考..." + 动画 | 无 |
| `processing` | "正在执行任务..." + 工具卡片 | 取消 |
| `streaming` | 文字逐字出现 + 光标 | 停止生成 |
| `complete` | 正常显示 | 复制、重新生成 |
| `error` | 错误提示 + 重试按钮 | 重试、取消 |

## 五、边界场景处理

### 5.1 快速连续发送多条消息

**用户行为**：用户在 Agent 回复完成前又发送了新消息

**处理策略**：
1. **阻止**：在 Agent 回复期间，输入框禁用，显示 "Agent 正在回复中..."
2. **队列**：新消息进入等待队列（最多 3 条）
3. **提示**：如果有排队消息，显示 "还有 2 条消息等待处理"

```
┌─────────────────────────────────────────┐
│ [输入框 - 禁用状态]                       │
│ Agent 正在回复中...                       │
│ 排队消息: 2 条                            │
└─────────────────────────────────────────┘
```

### 5.2 流式输出中断

**场景**：Agent 回复到一半，网络断开或服务端崩溃

**处理策略**：
1. 检测到断开后，立即停止流式动画
2. 保留已接收到的内容
3. 显示"连接已断开"提示，提供"重新连接"按钮
4. 用户选择重新连接后，尝试从中断处恢复（如果服务端支持）

### 5.3 首 Token 特别慢（TTFT > 5s）

**问题**：用户等待很久才看到第一个字

**缓解策略**：
1. **立即反馈**：发送后 <100ms 显示"正在思考..."
2. **进度提示**：3 秒后显示"正在分析您的请求..."
3. **估算时间**：如果有历史数据，显示"预计还需 X 秒"
4. **取消选项**：10 秒后显示"取消"按钮

### 5.4 Agent 调用多个工具

**场景**：Agent 依次调用 3 个工具（search → read → write）

**UI 策略**：
```
Agent: 我来帮你处理这个任务...

┌─────────────────────────────────┐
│ ✅ search_database (0.8s)        │
│ ⏳ read_file (执行中...)          │
│ ⏸️ write_file (等待中)            │
└─────────────────────────────────┘
```

## 六、验收标准（AC）

### AC1: 即时反馈
**Given** 用户在聊天框输入消息并点击发送
**When** 消息发送成功
**Then**
- 用户消息立即出现在聊天界面（<100ms）
- 下方出现 "正在思考..." 提示
- 输入框被禁用

### AC2: 文字流式输出
**Given** Agent 开始回复
**When** 回复内容包含文字
**Then**
- 文字按字符或小词组逐步出现（非整块出现）
- 输出速度约 30-50 字/秒
- 末尾有闪烁光标直到完成

### AC3: 工具调用可视化
**Given** Agent 调用了工具（如查询数据库）
**When** 工具开始执行
**Then**
- 显示工具名称和输入参数
- 显示"执行中..."状态
- 工具完成后显示耗时和结果摘要

### AC4: 长时间等待处理
**Given** Agent 执行时间超过 30 秒
**When** 用户正在等待
**Then**
- 显示已等待时间
- 提供"取消"按钮
- 取消后显示"已取消"状态

### AC5: 网络异常恢复
**Given** SSE 连接在流式输出中断开
**When** 检测到连接断开
**Then**
- 保留已接收到的内容
- 显示错误提示和"重新连接"按钮
- 点击"重新连接"后尝试恢复（或从头开始）

### AC6: 并发消息处理
**Given** Agent 正在回复
**When** 用户尝试发送新消息
**Then**
- 输入框显示"Agent 正在回复中..."
- 新消息不被发送
- 用户无法点击发送按钮

## 七、数据指标

### 关键指标
1. **TTFT（首 Token 时间）**：目标 < 2s
2. **TBT（首字节时间）**：目标 < 500ms
3. **流式流畅度**：卡顿次数 < 1 次/百字
4. **用户等待耐心**：30 秒取消率 < 10%

### 监控方式
- 前端埋点：记录各状态转换时间
- 后端日志：记录 Engine 创建时间、首个事件时间

---

## 八、非技术用户体验要点

1. **不说技术术语**：
   - ❌ "正在建立 SSE 连接..."
   - ✅ "正在连接..."

2. **错误信息友好**：
   - ❌ "Network Error: 503"
   - ✅ "服务暂时不可用，请稍后重试"

3. **进度可见**：
   - 总是让用户知道系统在做什么
   - 避免长时间无反馈

4. **可撤销性**：
   - 长时间操作提供"取消"按钮
   - 错误后提供"重试"选项
